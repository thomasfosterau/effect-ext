# @thomasfosterau/effect-platform-browser

## 0.2.0

### Minor Changes

- [#232](https://github.com/thomasfosterau/effect-ext/pull/232) [`b792ce3`](https://github.com/thomasfosterau/effect-ext/commit/b792ce3817fe956e764d186d3a4005e1990ddf59) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - `Credentials` gains the rest of the Credential Management API: `storePassword` and `password` (`PasswordCredential`), `identity` and `disconnectIdentity` (FedCM), and `preventSilentAccess`, with a `Network` failure reason for FedCM. `TestCredentials` gains a password store and scripted identity providers.

- [#230](https://github.com/thomasfosterau/effect-ext/pull/230) [`8b56c61`](https://github.com/thomasfosterau/effect-ext/commit/8b56c61489a9053e3c90d0421eaa14bcce0657f7) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `FileDrop` to effect-platform-browser: `drops(target)` streams each drop onto an element as its items, each a `File` or `Directory` handle (Chromium's `getAsFileSystemHandle`, the same handles `FilePicker` returns, so a dropped directory becomes a `FileSystem` through `BrowserFileSystem`) or, where the agent has none, a `Blob` with the dropped `File`. `BrowserTesting` gains `TestFileDrop`, a drop target whose `Control` drops paths from an in-memory disk.

- [#229](https://github.com/thomasfosterau/effect-ext/pull/229) [`a2fb0fe`](https://github.com/thomasfosterau/effect-ext/commit/a2fb0fe64cca255b2bd0454ef6f8d160b071e91b) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds handle permissions to `FilePicker`: `permission(handle, mode)` reads a file or directory handle's permission (`granted`, `denied` or `prompt`) and `requestPermission(handle, mode)` asks the user for it, failing `NotAllowed` without a user gesture. `fileSystem` takes a stored directory `handle` in place of the picker, asking for the permission it lacks first. `TestFilePicker`'s `Control` gains `stored`, `setPermission`, `respondToRequest` and `permissionRequests`, and the handles it picks answer permission calls.

- [#236](https://github.com/thomasfosterau/effect-ext/pull/236) [`d4e6fc5`](https://github.com/thomasfosterau/effect-ext/commit/d4e6fc52ff67ee4a8151fa9d2da7bd15eaa02300) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Brand every `Schema` error and value class (`Schema.TaggedError<Self, { readonly brand: unique symbol }>`, and the same on effect-ext's AI response classes such as `ClassifyResponse`, `RerankResponse` and `SpeechResponse`). A structurally identical object no longer type-checks where one of these classes is expected: construct it with `new` instead.

- [#237](https://github.com/thomasfosterau/effect-ext/pull/237) [`115b582`](https://github.com/thomasfosterau/effect-ext/commit/115b58281c8dd5722513e6aad7ff87147df57720) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Speaker` and `Dictation` to effect-ext: provider-neutral services for speech said out loud on the device (`say`) and live speech to text (`listen`, a stream of `Transcript` readings), each built with `make` and failing only with `AiError`.
  
  effect-platform-browser now depends on effect-ext and adds two modules. `AudioOutput` plays audio bytes through an `<audio>` element, finishing when the clip ends; `Browser.layer` includes it, and `BrowserTesting` adds `TestAudioOutput`. `LiveSpeech` provides `Speaker` and `Dictation` as layers over the browser: `speakerFromSynthesis` (the browser's own voices), `speakerFromModel` (any `SpeechModel`, played through `AudioOutput`) and `dictationFromRecognition` (the browser's own recogniser), mapping each browser failure onto an `AiError` reason.

## 0.1.0

### Minor Changes

- [#214](https://github.com/thomasfosterau/effect-ext/pull/214) [`da28834`](https://github.com/thomasfosterau/effect-ext/commit/da288348abeaca4dd71d83509e9b4e3b58a282ac) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Bluetooth`: Web Bluetooth's picker (`request`), `devices`, `availability`, and a scoped GATT connection (`connect`) whose services and characteristics `read`, `write` and stream `notifications`, failing `Disconnected` when the link drops. `Browser.layer` includes it, and `BrowserTesting` adds `TestBluetooth`, an in-memory GATT tree with a `Control` that answers the picker, drops links and pushes notifications.

- [#172](https://github.com/thomasfosterau/effect-ext/pull/172) [`c36ba2b`](https://github.com/thomasfosterau/effect-ext/commit/c36ba2b2eb3ff3163513af7fdb1a70f7246ab048) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds the browser services that were effect-ext's `Browser`, one subpath each: `Locks`, `Navigator`, `PageVisibility`, `MediaQuery`, `WakeLock`, `Broadcast`, `IdleDetection`, `Battery`, `Fullscreen`, `ScreenOrientation`, `Notifications` and `PermissionStatus`, with `Browser.layer` providing them all. `BrowserTesting` holds the in-memory doubles for them and for `@effect/platform-browser`'s services. `@effect/platform-browser` is now a peer.

- [#193](https://github.com/thomasfosterau/effect-ext/pull/193) [`a69b6e8`](https://github.com/thomasfosterau/effect-ext/commit/a69b6e8f38252134fbf2759f402bddf9ea385538) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `CookieStore` to effect-platform-worker-shared: cookies in a window and a service worker over the Cookie Store API, falling back to `document.cookie` (through `effect/http/Cookies`) where a window lacks it, with `get`, `getAll`, `set` (`expires` as a `DateTime`), `remove`, a `changes` stream, and `cookie(name, schema)` for one cookie read, written and watched through a schema. effect-platform-browser's `BrowserTesting` gains `TestCookieStore`, an in-memory jar behind either API.

- [#187](https://github.com/thomasfosterau/effect-ext/pull/187) [`199544e`](https://github.com/thomasfosterau/effect-ext/commit/199544e9b0f6f8c0b0288a52c3d280cba8ec037a) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `Credentials`: passkeys (WebAuthn) in the JSON shapes a server sends and expects back, with schemas for the creation and request options and both responses, `register`, `authenticate` (conditional mediation included), `capabilities` and the credential signals. `TestCredentials` is an in-memory authenticator. `Credentials` is in `Browser.layer`.

- [#173](https://github.com/thomasfosterau/effect-ext/pull/173) [`a729e08`](https://github.com/thomasfosterau/effect-ext/commit/a729e0873f6d2ef51b84e0a451f3e9f2e251718f) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `DomObservers`: `IntersectionObserver`, `ResizeObserver` and `MutationObserver` as streams (`intersection`, `resize`, `mutation`), each owning one observer for the stream's lifetime, plus `awaitVisible` and `whileVisible`. `Browser.layer` provides it, and `BrowserTesting`'s `TestDomObservers` doubles it.

- [#188](https://github.com/thomasfosterau/effect-ext/pull/188) [`36a0426`](https://github.com/thomasfosterau/effect-ext/commit/36a04261a50ddffc5a3644253608d0646f279e1b) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `EventSource` to effect-platform-worker-shared: server-sent events in a window and in dedicated and shared workers, as a stream of `effect/encoding/Sse` events through the browser's own reconnects, with `events(url, schema)` to decode JSON payloads. `EventSourceClient` is a context reference that defaults to the ambient `EventSource`. effect-platform-browser's `BrowserTesting` gains `TestEventSource`, an in-memory server.

- [#178](https://github.com/thomasfosterau/effect-ext/pull/178) [`3819ce1`](https://github.com/thomasfosterau/effect-ext/commit/3819ce16c7aac48abee4dab6a5fa7aa6d5f3e589) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `BrowserFileSystem`, Effect's `FileSystem` over the origin-private file system in a window or any worker, and `MemoryFileSystemHandle`, an in-memory directory handle for tests. Add `FilePicker` to the browser package (the File System Access open, save and directory pickers, with `fileSystem` to work in a picked directory through `FileSystem`) and its `TestFilePicker` double.

- [#213](https://github.com/thomasfosterau/effect-ext/pull/213) [`7d93aac`](https://github.com/thomasfosterau/effect-ext/commit/7d93aac4d55404268eb9220ce51aa25f137ad460) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `Hid` to `effect-platform-worker-shared`: WebHID from a window or a dedicated worker. `request`, `devices` and `connections` reach the granted devices; `open` holds a device for a scope and returns a `Handle` that streams its input reports and sends output and feature reports. `BrowserTesting` gains `TestHid`, in-memory devices to drive it.

- [#205](https://github.com/thomasfosterau/effect-ext/pull/205) [`bc03884`](https://github.com/thomasfosterau/effect-ext/commit/bc03884599326079978301f98d922b4031156280) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `AppBadge` to effect-platform-worker-shared: the Badging API (`set(count?)`, `clear`) from a window or a service worker, as a context reference over the ambient `navigator`.
  
  Add `InstalledApp` to effect-platform-browser: the deferred install prompt (`installPrompt`, `installable`, `prompt`), `installed`, the launch queue's `launches` (with file handles), `relatedApps`, and `displayMode` / `displayModeChanges` over `MediaQuery`. `Browser.layer` includes it. `BrowserTesting` adds `TestInstalledApp` and `TestAppBadge`.

- [#182](https://github.com/thomasfosterau/effect-ext/pull/182) [`fc10d3c`](https://github.com/thomasfosterau/effect-ext/commit/fc10d3ccc61c0371b7c21064393cd7b85677390e) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `MediaDevices`: camera, microphone and screen capture as scoped streams whose tracks stop when the scope closes; the device list and its changes; `trackEnded` and `attach`; and `record`, which turns a stream into the `MediaRecorder`'s `Blob` chunks. `Browser.layer` provides it, and `BrowserTesting`'s `TestMediaDevices` doubles devices, captures and the recorder.

- [#176](https://github.com/thomasfosterau/effect-ext/pull/176) [`7262d5a`](https://github.com/thomasfosterau/effect-ext/commit/7262d5a2dd3973762f3c220adc713fb4159a2609) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Navigation`: the current URL and its changes, `navigate`, `back` and `forward`, history state typed by a `Schema`, and `intercept`, which runs an Effect for each navigation a router takes over. It works over the Navigation API, falling back to `history` and `popstate` where the browser lacks it. `Browser.layer` provides it, and `BrowserTesting`'s `TestNavigation` doubles both modes.

- [#175](https://github.com/thomasfosterau/effect-ext/pull/175) [`147be83`](https://github.com/thomasfosterau/effect-ext/commit/147be83ee06f5ad000bcf418cfafa0871ab3d1da) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Performance` to effect-platform-worker-shared: high-resolution time, user timing (`mark`, `measure`, `timed`) and the performance timeline as a stream (`observe`), the same in a window and every worker, as a context reference over the ambient `performance`. Add `WebVitals` to effect-platform-browser: LCP, CLS, INP, FCP and TTFB as streams over that timeline, each a pure fold that runs over fixture entries, plus `BrowserTesting`'s `TestPerformance`, a timeline on a manual clock.
