# @thomasfosterau/effect-platform-browser

[Effect](https://effect.website) services for browser main-thread APIs that `@effect/platform-browser` does not cover: Web Locks, `navigator`, page visibility, media queries, the screen wake lock, `BroadcastChannel`, idle detection, the battery, fullscreen, screen orientation, the page's notifications and permission state, plus the page's side of a service worker (registering, updates, the controller as a schema-typed endpoint) and Web Push subscriptions. Every service has an in-memory double in `BrowserTesting`. It builds on [`@thomasfosterau/effect-platform-worker-shared`](../effect-platform-worker-shared); the worker's side of a service worker is [`@thomasfosterau/effect-platform-service-worker`](../effect-platform-service-worker).

> [!CAUTION]
> Experimental and pre-1.0. APIs may change between minor versions; pin what you use.

## Install

```sh
pnpm add @thomasfosterau/effect-platform-browser @effect/platform-browser effect
```

`effect` and `@effect/platform-browser` (`^4.0.0`) are peer dependencies: keep a single copy of each in your app. `@thomasfosterau/effect-platform-worker-shared` and `@thomasfosterau/effect-ext` come with it.

The platform services were `@thomasfosterau/effect-ext/Browser` and `/BrowserTesting`. Each service is now its own subpath and a namespace on the barrel (`import { Locks } from "@thomasfosterau/effect-platform-browser"`), the all-services `layer` is `Browser.layer`, and the doubles are `@thomasfosterau/effect-platform-browser/BrowserTesting`. Each service's `Context` key moved too (`@thomasfosterau/effect-ext/Browser/Locks` is now `@thomasfosterau/effect-platform-browser/Locks`), so move every import at once.

## Modules

| Module | What it is |
| --- | --- |
| `Locks`, `Navigation`, `Navigator`, `PageVisibility`, `MediaQuery`, `WakeLock`, `Broadcast`, `IdleDetection`, `Battery`, `Fullscreen`, `ScreenOrientation`, `Notifications`, `PermissionStatus`, `DomObservers`, `FilePicker`, `FileDrop`, `MediaDevices`, `SpeechSynthesis`, `SpeechRecognition`, `AudioOutput`, `Credentials`, `Frames`, `InstalledApp`, `Bluetooth` | One platform service each; see [Platform services](#platform-services). |
| `LiveSpeech` | effect-ext's `Speaker` and `Dictation` as layers over the browser: `speakerFromSynthesis` (its own voices), `speakerFromModel` (any `SpeechModel`, played through `AudioOutput`) and `dictationFromRecognition` (its own recogniser, listening continuously). Every failure leaves as an `AiError`. |
| `WebVitals` | LCP, CLS, INP, FCP and TTFB as streams over the performance timeline, each a pure `Fold` you can run over fixture entries. |
| `Browser` | `layer`: every live service, plus `@effect/platform-browser`'s `Clipboard`, `Geolocation` and `Permissions`. |
| `BrowserTesting` | In-memory doubles for every service, each with a `Control`; `observe`. Not on the barrel. |
| `ServiceWorkerContainer` | `navigator.serviceWorker` as typed effects: `register`, `ready`, `getRegistration`, `update`, `unregister`; the `controller` and `controllerChanges`; `waitingWorker` ("a new version is ready"); and `controllerEndpoint`, the controller as a `WorkerMessaging` endpoint. Every failure is a `ContainerError`. |
| `PushManager` | `registration.pushManager`: `subscribe`, `getSubscription`, `unsubscribe`, `permissionState`, and `toJson` checked against the `SubscriptionJson` schema a server can decode with too. Every failure is a `PushError`. |

`ServiceWorkerContainer.Container` is a context reference defaulting to `navigator.serviceWorker`, read on first use, so a page provides nothing and a test provides a stub.

More services are planned in [#152](https://github.com/thomasfosterau/effect-ext/issues/152).

## Usage

Every service module has the same shape: a `Context.Service` tag, a `make` over a structural `*Like` slice of the platform object (omit the argument for the unsupported service), a live `layer` that reads the ambient global when it is built (never at import), a tagged error whose `reason` maps the platform's `DOMException` names, and accessors. A live layer builds in any context — a missing API degrades (`supported: false`, an `Unsupported` failure, `Option.none()`) rather than failing the layer — so one layer serves every browser, a worker and a server render.

```ts
import * as Effect from "effect/Effect";
import { Browser, Locks, Navigator, PageVisibility } from "@thomasfosterau/effect-platform-browser";

// One tab refreshes the session on behalf of every tab of the origin.
const refresh = Effect.gen(function* () {
  yield* Navigator.awaitOnLine;
  return yield* fetchFreshToken; // your effect
}).pipe(Locks.withLock("auth-refresh"));

// Poll only while somebody can see the page.
const poll = PageVisibility.whileVisible(syncInbox.pipe(Effect.repeat(everyMinute)));

Effect.runFork(Effect.provide(Effect.all([refresh, poll], { concurrency: 2 }), Browser.layer));
```

## Testing browser code

`BrowserTesting`'s doubles run the **real** adapter over an in-memory platform object, so a test exercises the code that runs in the browser. Each module's `layer` provides the service and its `Control`; drive the platform through the `Control` (the double fires the events the browser would), and read back what the code under test asked of it.

```ts
import * as Effect from "effect/Effect";
import * as Fiber from "effect/Fiber";
import { Navigator } from "@thomasfosterau/effect-platform-browser";
import { TestNavigator, observe } from "@thomasfosterau/effect-platform-browser/BrowserTesting";

const program = Effect.gen(function* () {
  const control = yield* TestNavigator.Control;
  // Subscribe first: `observe` returns once the stream has emitted its current value.
  const seen = yield* observe(Navigator.onLineChanges, 2);
  yield* control.setOnLine(false);
  return yield* Fiber.join(seen); // [true, false]
});

Effect.runPromise(Effect.provide(program, TestNavigator.layer()));
```

Fork-then-sleep is a race (the child may not have subscribed yet); `observe` is the sync point. `TestLocks.makeLockManager()` is one origin: build several `Locks` services over it (`Locks.make(manager.forClient("tab-b"))`) to test contention between tabs.

## Platform services

Each module is a namespace on the barrel and its own subpath: `import { Locks } from "@thomasfosterau/effect-platform-browser"`, then `Locks.Locks` (the tag), `Locks.layer`, `Locks.make`, `Locks.withLock`, ….

- `Locks` — Web Locks. `acquire(name, { mode?, steal? }): Effect<HeldLock, LockError, Scope>` holds an origin-wide lock until the scope closes; waiting is interruptible (the request is withdrawn), and closing the scope waits for the browser to report the release. `tryAcquire` is `ifAvailable` (`None` instead of queueing). `withLock(name, options?)` runs an effect under the lock and, if another context steals it, interrupts the effect and fails `Stolen`; `withLockIfAvailable` runs it only when the lock is free (leader election). `query` is a diagnostic snapshot. `LockError.reason`: `Unsupported`, `Stolen`, `InvalidRequest`, `NotAllowed`, `InvalidState`, `Failed`.
- `Navigator` — `info` (user agent, languages, `hardwareConcurrency`, `deviceMemoryGiB`, touch points, cookies, `webdriver`, Global Privacy Control); `onLine` / `onLineChanges` / `awaitOnLine`; `languages` / `languageChanges`; `connection` / `connectionChanges` (Network Information, `None` where missing); `userActivation`; `canShare` / `share`; `sendBeacon`; `vibrate`; `storage.estimate` / `persisted` / `persist`. `NavigatorError` carries the `operation` and a `reason` (`Unsupported`, `NotAllowed`, `Aborted` — the user dismissed the share sheet, `InvalidData`, `InvalidState`, `Rejected` — the beacon was not queued, `Failed`).
- `PageVisibility` — `state`, `changes`, `awaitVisible`, and `whileVisible(effect)`: started whenever the page becomes visible, interrupted whenever it is hidden.
- `MediaQuery` — `matches(query)`, `changes(query)`, and the preference streams `colorScheme`, `reducedMotion`, `moreContrast`, `reducedData`.
- `WakeLock` — the Screen Wake Lock. `acquire` is scoped; `keepAwake(effect)` holds one lock for the effect and fails `WakeLockError` without one; `keepAwakeWhileVisible(effect)` re-acquires each time the page returns (the browser drops the lock on hide) and never fails the effect over a lock it could not get.
- `IdleDetection` — `IdleDetector` (Chromium-only, behind a permission: treat it as optional; `supported: false` is the common case). `requestPermission` (from a user gesture) returns `"granted" | "denied"`; `watch({ threshold })` is a `Stream<IdleState, IdleError>` of `{ user: "active" | "idle", screen: "locked" | "unlocked" }`, current state first, and its detector is aborted when the stream ends. `threshold` is a `Duration.Input` of at least `minimumThreshold` (one minute). `IdleError.reason`: `Unsupported`, `NotAllowed` (permission not granted, or no activation to ask with), `InvalidRequest` (threshold under a minute), `Failed`.
- `Bluetooth` — Web Bluetooth (Chromium, in a window only). `request(options)` shows the picker from a user gesture (`filters`, or `acceptAllDevices`, plus the `optionalServices` a connection may reach) and fails `NotFound` when the user closes it; `devices` lists the devices the page may reconnect to (`Unsupported` where the agent has no `getDevices`); `availability` is whether there is an adapter, then each change (`false` alone without the API). `connect(device)` is a scoped GATT connection: `service(uuid)`, then `characteristic(uuid)`, whose `read`, `write(data, { response? })` and `notifications` (a stream that turns notifications on, and off when it ends; run one per characteristic) do the work. Every call fails `Disconnected` once the link drops and `Closed` after the scope, which disconnects the device. UUIDs are full strings, 16- or 32-bit aliases (`0x180d`) or names; `canonicalUuid` expands an alias. `BluetoothError` carries the `operation` and a `reason`: `Unsupported`, `NotFound`, `NotAllowed`, `NotSupported`, `InvalidState`, `Disconnected`, `Closed`, `Failed`.
- `Battery` — `navigator.getBattery()` (Chromium-only; Firefox and Safari removed it). Its own service, not part of `Navigator`, because the manager is promise-acquired (once, on the first reading). `status` is an `Option<BatteryState>` — `{ charging, level (0–1), chargingTime, dischargingTime }`, the times `Option<Duration>` with the API's `Infinity` (unknown) as `None` — and `changes` follows the four change events; `None` / empty where the API is missing or `getBattery()` rejects.
- `Fullscreen` — `enter(element, options?): Effect<void, FullscreenError, Scope>` shows an element fullscreen; closing the scope calls `exitFullscreen()` only if that element is still the fullscreen one. `withFullscreen(element, options?)` is the combinator form (the user leaving with Esc does not interrupt it). `element` (`Option`) and `changes` follow `fullscreenchange`. Unprefixed API only; Safari on iPhone reads as unsupported. `FullscreenError.reason`: `Unsupported` (no API, or `fullscreenEnabled` is `false`), `NotAllowed` (no user activation, a permissions policy), `Failed`.
- `ScreenOrientation` — `type`, `angle` (`Option`), `current`, and `changes` (follows `change`; empty where missing). `lock(orientation)` is scoped and unlocks when the scope closes; `withLock(orientation)` is the combinator form, and composes inside `Fullscreen.withFullscreen`, where browsers allow a lock. `OrientationError.reason`: `Unsupported` (no API or no `lock`, or a `NotSupportedError` refusal), `NotAllowed` (`SecurityError`), `Aborted` (a newer lock superseded it), `Failed`.
- `Notifications` — the page's own `Notification`s. `permission` (`None` where unsupported); `requestPermission` returns the user's answer and fails `NotAllowed` without transient user activation; `show(title, options?): Effect<ShownNotification, NotificationError, Scope>` closes the notification when the scope closes, and its `clicks` / `closes` streams replay from when it was shown, end once it closes and fail `Failed` on the browser's `error` event; `permissionChanges` follows `PermissionStatus.changes("notifications")`. `NotificationError.reason`: `Unsupported`, `NotAllowed` (not yet granted, or no activation), `Denied`, `InvalidData`, `Failed`. Service-worker-registration notifications (`registration.showNotification`, `notificationclick`) are not here: they outlive the page and their events reach the worker, so they belong with [`@thomasfosterau/effect-platform-service-worker`](../effect-platform-service-worker)'s `Notifications`.
- `Broadcast` — `BroadcastChannel`. `channel(name, schema)` opens a scoped channel whose `publish` encodes and whose messages are decoded through the schema (an undecodable message from another tab — an older deploy — is dropped with a warning log). `subscribe` starts listening when it runs, so nothing posted before the stream is consumed is lost; `messages` listens from when it runs. `open(name)` is the undecoded form.
- `DomObservers` — `IntersectionObserver`, `ResizeObserver` and `MutationObserver` as streams, one observer per subscription, disconnected when the stream ends. `intersection(target, options?)` and `resize(target, options?)` emit the target's state as soon as it is observed, then each change, as plain data (`rootBounds` is an `Option`; box sizes missing from older Safari are empty). `mutation(target, options)` emits each batch of records in order, nothing on subscribe. `awaitVisible(target)` waits until the target is in view; `whileVisible(target)` runs an effect once it is, returning `None` and interrupting it if the target leaves first. `DomObserverError` carries the `observer` and a `reason`: `Unsupported` (a server render, a worker), `InvalidOptions` (a malformed `rootMargin`, a threshold outside 0–1, mutation options that observe nothing), `Failed`.
- `Navigation` — same-document navigation over the Navigation API, falling back to `history` / `popstate` / `hashchange` where it is missing (older Firefox and Safari). `current` (`Option<URL>`) and `changes`; `navigate(url, { replace?, state? })`, which with the Navigation API completes once every handler finished; `back` and `forward`; `state(schema)` decodes the current entry's state (`None` when it does not decode: one written by an older deploy) and `setState(schema, value)` encodes and replaces it. `intercept(handler)` is the router primitive: for each navigation the page may intercept (same-origin, not a download), `handler` returns `Option` of an effect that renders the destination; the URL changes at once, `navigate` completes when the effect does, a newer navigation interrupts it, and closing the scope stops intercepting. Route matching stays with the caller. With only the fallback, `intercept` fails `Unsupported`, and a cross-origin `navigate` loads the page through `location`. `NavigationError.reason`: `Unsupported`, `InvalidUrl`, `NotSerializable` (state the structured-clone algorithm, or the schema, rejects), `Aborted` (a newer navigation superseded it), `InvalidState` (nothing to go back or forward to), `Failed` (an intercept handler failed).
- `FileDrop` — `drops(target)`: each drop onto an element as its items, each a `File` or `Directory` handle (Chromium's `getAsFileSystemHandle`) or, where the agent has none, a `Blob` with the dropped `File`. While it runs, the element accepts drops.
- `FilePicker` — the File System Access pickers (Chromium, from a user gesture): `open` (one or more file handles), `save` (a file handle, created if new) and `directory` (a directory handle), each with the platform's options (`types`, `id`, `startIn`, `suggestedName`, `mode`). `fileSystem(options)` picks a directory (or takes a stored `handle`, asking for its permission first) and returns an Effect `FileSystem` rooted at it, over `effect-platform-worker-shared`'s `BrowserFileSystem`; `permission(handle, mode)` and `requestPermission(handle, mode)` read and ask for a handle's permission (`granted`, `denied`, `prompt`), for a handle stored and read back in a later session; `optional(effect)` turns a closed picker into `Option.none()`. `FilePickerError.reason`: `Unsupported`, `Aborted` (the user closed it), `NotAllowed` (no user gesture, a cross-origin frame), `Failed`.
- `Frames` — `requestAnimationFrame` and `requestIdleCallback`. `next` is the next frame's time; `ticks` streams every frame as `{ time, delta }` (a slow consumer sees the latest eight, and a hidden tab's paused frames are absent, so expect a long `delta` on return); `idle({ timeout? })` waits for an idle period and reports its `didTimeout` and `timeRemaining` as they stood at the callback. Interrupting any of them cancels its request. A missing API fails `FramesError` (`reason: "Unsupported"`, `api: "animationFrame" | "idleCallback"`): a worker has neither, Safari has no idle callbacks. For long Effect work that should not block input, run it on [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `TaskScheduler`.
- `InstalledApp` — the page as an installable web app. `beforeinstallprompt` fires once, early, so `layer` listens from the moment it builds (build it at startup) and holds the event: `installPrompt` is the held prompt (`Some({ platforms })`) and `installable` follows whether one is held, for an "Install" button; `prompt`, from a click, shows it and returns `"accepted"` or `"dismissed"`, after which it is gone. `installed` streams each `appinstalled`, from the prompt or the browser's menu. `launches` streams each launch (`targetUrl`, and the `files` of a file-handling or share-target launch, as handles `BrowserFileSystem` reads), starting with those queued before it ran; the browser hands launches to one consumer, so run one such stream. `relatedApps` lists the manifest's `related_applications` the user has installed. `displayMode` and `displayModeChanges` read the `display-mode` media feature through `MediaQuery` (`"browser"`, `"standalone"`, `"minimal-ui"`, `"fullscreen"`, `"window-controls-overlay"`, `"picture-in-picture"`). `InstalledAppError` carries the `operation` and a `reason`: `Unsupported` (Firefox and Safari have no install prompt), `NoPrompt` (none held: installed, not installable, or already shown), `NotAllowed` (no user gesture), `Failed`. The app badge is [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `AppBadge`, since a service worker sets it too.
- `MediaDevices` — cameras, microphones and screen capture. `userMedia(constraints)` and `displayMedia(options?)` are scoped: closing the scope stops every track, so the camera light goes off with the fiber. `devices` and `deviceChanges` (the current list first, then each plug or unplug); `supportedConstraints`; `trackEnded(track)` completes when the platform ends a track (unplugged, revoked, the user stopped sharing); `attach(element, stream)` shows a stream in a `<video>` for the scope. `record(stream, { mimeType?, timeslice?, until? })` is the `MediaRecorder` as a stream of `Blob` chunks, ending when the tracks end or, gracefully with the last chunk, when `until` completes: the audio effect-ext's `TranscriptionModel` takes. `MediaDevicesError.reason`: `Unsupported`, `NotAllowed`, `NotFound`, `NotReadable` (in use), `Overconstrained` (with `constraint`), `Aborted`, `Failed`; `MediaRecorderError.reason`: `Unsupported`, `NotSupported`, `Failed`.
- `Credentials` — passkeys (WebAuthn), in the JSON shapes a server sends and expects back. The schemas `CreationOptionsJson` and `RequestOptionsJson` decode the server's options; `register(options)` and `authenticate(options, mediation?)` run the ceremony and return a `RegistrationResponseJson` / `AuthenticationResponseJson` ready to post back (the same schemas decode it on the server). The platform's `parse*FromJSON` is used where the agent has it, with the base64url conversion done by hand where it does not; binary extension outputs (`prf`, `largeBlob`) come back as base64url. Interrupting a ceremony aborts it, which is how a page stops a `"conditional"` (autofill) sign-in that would otherwise wait for ever. `capabilities` is `getClientCapabilities()`, or the two older checks (`conditionalGet`, `userVerifyingPlatformAuthenticator`) where the agent lacks it. `signalUnknownCredential`, `signalAllAcceptedCredentials` and `signalCurrentUserDetails` keep the user's passkey provider in step with the server. `CredentialsError.reason`: `Unsupported`, `NotAllowed` (cancelled, timed out, or no matching passkey: WebAuthn does not say which), `InvalidState` (already registered), `Security` (RP id mismatch), `NotSupported` (no supported algorithm), `Constraint`, `Aborted`, `Encoding` (a malformed base64url field), `Failed`. Verifying a response is the server's job. The rest of the Credential Management API sits on the same service: `storePassword({ id, password, name?, iconURL? })` offers to save a password after a form sign-in and `password(mediation?)` fills one back as an `Option` (both `Unsupported` outside Chromium; `passwordsSupported` says which), `identity({ providers, context?, mode? }, mediation?)` signs in through a FedCM identity provider and returns its `token`, `isAutoSelected` and `configURL` (interrupting it aborts the prompt; `identitySupported`; failures the provider reports are `Network`), `disconnectIdentity` asks a provider to forget an account, and `preventSilentAccess` after a sign-out makes the next password or identity sign-in ask. `FederatedCredential` is not wrapped: FedCM replaces it.
- `SpeechSynthesis` — text to speech through the browser's own voices. `speak(text, { lang?, voice?, pitch?, rate?, volume? })` completes when the utterance ends; concurrent calls take turns on the page's one queue, and interrupting a call stops its voice. `boundaries(text, options?)` speaks too, as the word and sentence boundaries it reaches (what a read-along highlight follows). `voices` waits up to a second for a voice list that loads late (Chromium); `voiceChanges` follows it. `pause`, `resume` and `cancel` act on the whole queue. `SpeechSynthesisError.reason`: `Unsupported`, `NotAllowed`, `VoiceUnavailable`, `LanguageUnavailable`, `TextTooLong`, `AudioBusy`, `Network`, `Interrupted` (another caller cancelled the queue), `Failed`. It plays audio and returns none, so it is not an effect-ext `SpeechModel`; `LiveSpeech.speakerFromSynthesis` makes it an effect-ext `Speaker`.
- `SpeechRecognition` — speech to text from the microphone (`SpeechRecognition`, or the prefixed `webkitSpeechRecognition`). `listen({ lang?, continuous?, interimResults?, maxAlternatives?, processLocally?, until? })` streams the engine's `Result`s (`index`, `isFinal`, `transcript`, `confidence`, `alternatives`; an interim result is replaced by later ones with the same `index`), ending when the session does or, with what was already heard, when `until` completes; ending the stream early aborts the session. Silence ends the session without failing. `once(options?)` is one phrase's final transcript, or `None`. `SpeechRecognitionError.reason`: `Unsupported`, `NotAllowed`, `AudioCapture`, `Network`, `LanguageNotSupported`, `Aborted`, `Failed`. It hears only the live microphone, so it is not an effect-ext `TranscriptionModel`; for that, record with `MediaDevices.record` and send the audio to a provider. `LiveSpeech.dictationFromRecognition` makes it an effect-ext `Dictation`.
- `AudioOutput` — plays audio bytes through an `<audio>` element over a blob URL: `play(audio, mediaType)` completes when the clip ends, and interrupting it pauses playback; the URL is revoked either way. It is the sink `LiveSpeech.speakerFromModel` plays a `SpeechModel`'s audio into. `AudioOutputError.reason`: `Unsupported` (no `Audio`: a worker, a server render), `NotAllowed` (no user gesture), `NotSupported` (a media type the agent cannot play), `Failed` (a decode error included).
- `WebVitals` — the Core Web Vitals and their diagnostics over [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `Performance` (a context reference defaulting to the page's own `performance`, so it needs no layer). Each metric is a `Fold` (`largestContentfulPaint`, `cumulativeLayoutShift`, `interactionToNextPaint`, `firstContentfulPaint`, `timeToFirstByte`): the entry type it observes, a pure `step`, and its `value`. `fold(metric, entries)` computes one from fixtures; `observe(metric)` emits a `Metric` (`name`, `value`, `rating` against `thresholds`) from the buffered entries on, each time the value changes, and ends empty where the browser does not record the entry type; `all` merges the five and `report(f)` runs `f` on each. Values follow the `web-vitals` library's definitions without its page-lifecycle handling: LCP is the latest candidate, CLS the largest session window, INP the slowest interaction less one outlier per 50.
- `PermissionStatus` — over `@effect/platform-browser`'s `Permissions`: `state(name)`, `changes(name)` (follows the status's `change` event), `awaitGranted(name)`.
- `Browser.layer` — every live service above plus `@effect/platform-browser`'s `Clipboard`, `Geolocation` and `Permissions`. Prefer the per-service layers where bundle size matters.

## `BrowserTesting` — doubles

- `TestLocks` — `makeLockManager({ clientId? })`, an in-memory lock manager following the Web Locks request algorithm (FIFO per name, shared/exclusive, `ifAvailable`, `steal`, `signal`, `query`), with `forClient(id)` views for other tabs; `layer(manager?)`.
- `TestNavigator` — `layer(options?)` / `make(options?)` with `Control`: `setOnLine`, `setLanguages`, `setConnection`, `setUserActivation`, and the recorded `shares`, `beacons`, `vibrations`. Options choose how `share` (`succeed` / `abort` / `deny` / `unsupported`) and `sendBeacon` (`queue` / `reject` / `unsupported`) answer.
- `TestPageVisibility`, `TestMediaQuery`, `TestWakeLock` (`held`, `requests`, `releaseAll`, `setDenied`), `TestBroadcast` (an in-memory hub with structured-clone semantics; `posted`, `deliver` a message from "another context").
- `TestIdleDetection` — `Control`: `setUser`, `setScreen` (fire `change` on running detectors), `setPermission`, `setAnswer`, `running`, `thresholds`. `TestBattery` — `Control`: `set({ charging?, level?, chargingTime?, dischargingTime? })` (fires the matching events), `requests`; options set the readings, `supported` and `reject`.
- `TestFullscreen` — `Control`: `element(id)`, `setAllowed`, `exit` (the user pressing Esc), `requests`. `TestScreenOrientation` — `Control`: `rotate(type, angle?)`, `locked`, `setRefusal(refusal?)` (no argument grants locks again); options choose the starting orientation and whether `lock` exists.
- `TestNotifications` — `layer(options?)` / `make(options?)` with `Control`: `setPermission`, `setAnswer` (what a prompt resolves to), `setUserActivation`, `click` / `dismiss` / `fail` the `index`th notification, and the recorded `shown` (each entry's `options` is an `Option`) and `requests`.
- `TestDomObservers` — `Control`: `element(id)` (a stand-in node), `setIntersecting(target, inView, ratio?)`, `setSize(target, size)` (each delivers an entry to the target's observers), `mutate(target, records)` (filtered by each observer's options, as the browser does), `observers(target, kind)`, and `awaitObserved(target, kind)`, the sync point before driving a `mutation` stream; options set the viewport and `supported`.
- `TestNavigation` — a session history behind an in-memory Navigation API (or, with `api: "history"`, `history`, `location` and the window's `popstate` / `hashchange`; `api: "none"` is the unsupported service). Every navigation commits, cross-document ones included. `Control`: `navigate(url, { download? })` follows a link as the user would, `back` and `forward` press the browser's buttons, `entries` and `index` read the history.
- `TestPerformance` — a `performance` timeline on a manual clock, providing `Performance`. `Control`: `advance(ms)`, `record(entries)` (adds to the timeline and delivers each to the observers of its type, as the browser does on a paint or a layout shift), `entries` (marks and measures included) and `observing`; options set the clock, the recorded `entryTypes` (`chromiumEntryTypes` by default), and whether `performance` and its observer exist.
- `TestCookieStore` — an in-memory cookie jar behind the Cookie Store API (or, with `api: "document"`, only `document.cookie`; `api: "none"` is the unsupported service), providing [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `CookieStore`. `Control`: `jar` (every attribute of each live cookie), `fromServer(cookie)` (as a response's `Set-Cookie`), `fromScript(header)` (another script writing `document.cookie`), `advance(ms)` (expires cookies on a manual clock, which `now` starts) and `failNext(name)`; every change fires `change`.
- `TestEventSource` — an in-memory server-sent events server, providing [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `EventSourceClient`; relative URLs resolve against `https://example.com/` (or the `baseUrl` you give). `Control`: `connected(url)` (the sync point before sending), `send(url, events)` (each with an optional `event` type and `id`), `drop(url)` (the browser reconnects, keeping the last event id), `refuse(url)` (it gives up) and `connections`.
- `TestFileDrop` — a drop target over an in-memory disk. `make({ handles? })` returns the `target` and a `Control`: `disk`, `listening` (waits for a drop listener), `drop(paths)`, `dropText` and `prevented`. `handles: false` drops plain `File`s, as outside Chromium.
- `TestFilePicker` — pickers over an in-memory disk. `Control`: `disk` (a `FileSystem` over it, to seed files and read back writes), `pick(paths)` (what the user picks next; `save` and `directory` create theirs), `cancel`, `deny`, `requests` (each picker opened, with its options), `stored(path)` (a directory handle as read back from storage, its permission `prompt`), `setPermission(handle, state)`, `respondToRequest(response)` (`grant`, `deny`, `dismiss`, or `refuse` as without a gesture) and `permissionRequests`. A picker with nothing queued is closed, and a permission prompt dismissed; picked handles start `granted`.
- `TestFrames` — frames and idle callbacks on a manual clock (`now`, and `frameDuration`, default 16 ms); `animation: false` or `idle: false` removes an API. `Control`: `frame(ms?)` waits for a frame to be requested, then moves the clock and runs every pending frame callback; `idle(period?)` does the same for idle callbacks (`timeRemaining` 50 ms and `didTimeout: false` by default); `pending` lists what waits, with each idle callback's timeout.
- `TestInstalledApp` — an installable app; `installPrompt: false`, `launchQueue: false` or `relatedApps: false` removes an API, and `installedRelatedApps` seeds the related apps. `Control`: `offerInstall(platforms?)` fires `beforeinstallprompt`; `answerWith(outcome)` sets the user's answer (`"accepted"` by default, which then fires `appinstalled`); `setUserActivation(false)` makes `prompt()` reject `NotAllowedError`; `install` fires `appinstalled` as the browser's menu does; `launch(params)` queues a launch until a consumer is set; `setRelatedApps`; `prompts` counts the prompts shown.
- `TestAppBadge` — an in-memory badge providing [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `AppBadge` (`supported: false` removes it). `Control`: `badge` (`Option` of a count or `"dot"`) and `failNext(name)`.
- `TestSerial` — in-memory serial ports providing [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `Serial` (`supported: false` removes the API, `picker: false` the picker, as in a worker). `Control`: `plug(options?)` returns a `TestSerialPort` (`granted: false` hides it until picked), `unplug(port)`, `pick(port)` for the next picker, and `requests`. A `TestSerialPort` `send`s bytes from the device, `fail(name)`s the current read, and records `written`, `options` and `signals`.
- `TestHid` — in-memory HID devices providing [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `Hid` (`supported: false` removes the API, `picker: false` the picker). `Control`: `plug(options?)` returns a `TestHidDevice` (its ids, name and `collections`; `granted: false` hides it until picked), `unplug(device)`, `pick(devices)` and `requests`. A `TestHidDevice` fires `input` reports while open, answers `receiveFeatureReport` from `feature`, and records what was `sent`.
- `TestBluetooth` — in-memory Bluetooth devices providing `Bluetooth` (`supported: false` removes the API, `getDevices: false` that method, `available` sets the adapter). `Control`: `add(options?)` returns a `TestBluetoothDevice` with its `id`, `name` and GATT `services` (`granted: false` hides it from `devices` until picked), `pick(device)` for the next picker, `requests`, `setInRange(device, inRange)` (out of range drops the link), `notify(device, service, characteristic, data)` and `setAvailable`. `device.characteristic(service, characteristic)` finds a `TestCharacteristic`, which allows `read`, `write` and `notify` unless told otherwise and records what was `written`.
- `TestUsb` — in-memory USB devices providing [`effect-platform-worker-shared`](../effect-platform-worker-shared)'s `Usb` (`supported: false` removes the API, `picker: false` the picker). `Control`: `plug(options?)` returns a `TestUsbDevice` (its ids, names and `configurations`; `granted: false` hides it until picked), `unplug(device)`, `pick(device)` and `requests`. A `TestUsbDevice` follows the platform's open, configure and claim order; it `send`s data on an IN endpoint, `reply`s to control reads, `stall`s an endpoint until `clearHalt`, and records `written`, `controls`, `claimed` and `alternates`.
- `TestMediaDevices` — a microphone, camera and speaker (or the `devices` you give), screen capture and a `MediaRecorder`, each switchable off. `Control`: `setDevices` (fires `devicechange`), `failNext(name, constraint?)`, `live`, `endTracks(kind?)` (as an unplug or a stopped share; a recorder whose tracks have all ended stops), `deliver(data)` (media for the recorders), `failRecording`, `recording` and `requests`.
- `TestCredentials` — an in-memory passkey authenticator for `example.com` (or the `rpId` you give): registration honours `excludeCredentials` and needs ES256 or RS256; a modal sign-in uses the first matching passkey; a conditional one waits for `pick`. Options switch off `parsers`, `clientCapabilities`, `level2` (the attestation accessors) and `signals`. It also keeps a password store and scripted identity providers (`passwords: false` and `identity: false` switch them off): a sign-in is silent where it can be (one stored password, or a client already signed in to, and no `preventSilentAccess` since), and otherwise takes the first password or the first offered provider with an account. `Control`: `passkeys`, `failNext(name)`, `waiting`, `pick(id)`, `signals`, `requests`, `passwords`, `dismissNext`, `identityAccount(configURL, token)`, `silentAccess` and `disconnects`.
- `TestSpeechSynthesis` — a synthesiser with an Australian English and a French voice (or the `voices` you give) that speaks each utterance at once, word by word. Options: `lateVoices` (none until `setVoices`, as Chromium loads them), `hold` (each utterance speaks until `finish`), `supported`. `Control`: `setVoices` (fires `voiceschanged`), `failNext(code)`, `speaking`, `finish`, `paused` and `spoken` (each utterance with its settings).
- `TestSpeechRecognition` — a recogniser that hears what `Control.say(readings)` says: one phrase as the engine's successive readings, the last one final, heard by the session listening now or else the next one. A session that is not `continuous` ends after one phrase, or with `no-speech` if there is nothing to hear. `Control`: `say`, `failNext(code)`, `listening` and `sessions` (how each was set up).
- `TestAudioOutput` — speakers that play each clip to the end at once (`hold` keeps it playing until `finish`; `supported: false` removes them). `Control`: `refuseNext(name)` (the next `play()` rejects with that `DOMException`), `failCurrent` (a decode error), `finish`, `playing`, `played` (each clip's `mediaType` and `byteLength`) and `openUrls` (blob URLs not yet revoked).
- `TestPermissions`, `TestClipboard`, `TestGeolocation` — doubles for the `@effect/platform-browser` services.
- `layer` — every double and every `Control` at once. `observe(stream, count)` — forks the first `count` elements and returns once the first is out.

## Service workers and push

Register a worker, offer an update when one is waiting, and subscribe to push:

```ts
import { Effect } from "effect";
import { PushManager, ServiceWorkerContainer } from "@thomasfosterau/effect-platform-browser";

// Your server's VAPID public key, base64url.
const VAPID_KEY = "BEl6...";

const program = Effect.gen(function* () {
  const registration = yield* ServiceWorkerContainer.register("/sw.js", { type: "module" });

  // Resolves once a new version has installed; the worker's message
  // listener calls `self.skipWaiting()`.
  yield* Effect.forkDetach(
    Effect.gen(function* () {
      const next = yield* ServiceWorkerContainer.waitingWorker(registration);
      if (confirm("A new version is ready. Reload?")) next.postMessage({ type: "SKIP_WAITING" });
    }),
  );

  const active = yield* ServiceWorkerContainer.ready;
  const subscription = yield* PushManager.subscribe(active, { applicationServerKey: VAPID_KEY });
  return yield* PushManager.toJson(subscription); // POST this to your server
});
```
