# @thomasfosterau/effect-platform-worker-shared

## 0.2.0

### Minor Changes

- [#236](https://github.com/thomasfosterau/effect-ext/pull/236) [`d4e6fc5`](https://github.com/thomasfosterau/effect-ext/commit/d4e6fc52ff67ee4a8151fa9d2da7bd15eaa02300) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Brand every `Schema` error and value class (`Schema.TaggedError<Self, { readonly brand: unique symbol }>`, and the same on effect-ext's AI response classes such as `ClassifyResponse`, `RerankResponse` and `SpeechResponse`). A structurally identical object no longer type-checks where one of these classes is expected: construct it with `new` instead.

- [#227](https://github.com/thomasfosterau/effect-ext/pull/227) [`16cc82a`](https://github.com/thomasfosterau/effect-ext/commit/16cc82af9fb07ebf02d5d4af0c696e0ca6baf7b8) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `Performance.layerTracer` and `Performance.measuredTracer`: wrap the current `Tracer` so that every sampled Effect span is also recorded as a user-timing measure (visible in the browser's performance panel) when it ends. Options filter spans by name and attach a span's cloneable attributes as the measure's `detail`. A refused measure is dropped, so tracing never fails the traced effect.

- [#231](https://github.com/thomasfosterau/effect-ext/pull/231) [`82b2c9d`](https://github.com/thomasfosterau/effect-ext/commit/82b2c9d8d376a543a52fd6bd0f984732242e41fc) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds sync access handles to `BrowserFileSystem`: `make(root, { syncAccess: true })`, `layerHandle(root, { syncAccess: true })` and the new `layerWorker` (OPFS in a dedicated worker) make `open` hold a `FileSystemSyncAccessHandle` for the file's scope, so reads and writes go in place under an exclusive lock instead of through a swap file each; a file already locked fails `Busy`, and a handle without sync access falls back to writables. `MemoryFileSystemHandle` gains in-memory sync access handles that lock the file as the platform does.

## 0.1.0

### Minor Changes

- [#193](https://github.com/thomasfosterau/effect-ext/pull/193) [`a69b6e8`](https://github.com/thomasfosterau/effect-ext/commit/a69b6e8f38252134fbf2759f402bddf9ea385538) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `CookieStore` to effect-platform-worker-shared: cookies in a window and a service worker over the Cookie Store API, falling back to `document.cookie` (through `effect/http/Cookies`) where a window lacks it, with `get`, `getAll`, `set` (`expires` as a `DateTime`), `remove`, a `changes` stream, and `cookie(name, schema)` for one cookie read, written and watched through a schema. effect-platform-browser's `BrowserTesting` gains `TestCookieStore`, an in-memory jar behind either API.

- [#188](https://github.com/thomasfosterau/effect-ext/pull/188) [`36a0426`](https://github.com/thomasfosterau/effect-ext/commit/36a04261a50ddffc5a3644253608d0646f279e1b) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `EventSource` to effect-platform-worker-shared: server-sent events in a window and in dedicated and shared workers, as a stream of `effect/encoding/Sse` events through the browser's own reconnects, with `events(url, schema)` to decode JSON payloads. `EventSourceClient` is a context reference that defaults to the ambient `EventSource`. effect-platform-browser's `BrowserTesting` gains `TestEventSource`, an in-memory server.

- [#178](https://github.com/thomasfosterau/effect-ext/pull/178) [`3819ce1`](https://github.com/thomasfosterau/effect-ext/commit/3819ce16c7aac48abee4dab6a5fa7aa6d5f3e589) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `BrowserFileSystem`, Effect's `FileSystem` over the origin-private file system in a window or any worker, and `MemoryFileSystemHandle`, an in-memory directory handle for tests. Add `FilePicker` to the browser package (the File System Access open, save and directory pickers, with `fileSystem` to work in a picked directory through `FileSystem`) and its `TestFilePicker` double.

- [#213](https://github.com/thomasfosterau/effect-ext/pull/213) [`7d93aac`](https://github.com/thomasfosterau/effect-ext/commit/7d93aac4d55404268eb9220ce51aa25f137ad460) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `Hid` to `effect-platform-worker-shared`: WebHID from a window or a dedicated worker. `request`, `devices` and `connections` reach the granted devices; `open` holds a device for a scope and returns a `Handle` that streams its input reports and sends output and feature reports. `BrowserTesting` gains `TestHid`, in-memory devices to drive it.

- [#205](https://github.com/thomasfosterau/effect-ext/pull/205) [`bc03884`](https://github.com/thomasfosterau/effect-ext/commit/bc03884599326079978301f98d922b4031156280) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `AppBadge` to effect-platform-worker-shared: the Badging API (`set(count?)`, `clear`) from a window or a service worker, as a context reference over the ambient `navigator`.
  
  Add `InstalledApp` to effect-platform-browser: the deferred install prompt (`installPrompt`, `installable`, `prompt`), `installed`, the launch queue's `launches` (with file handles), `relatedApps`, and `displayMode` / `displayModeChanges` over `MediaQuery`. `Browser.layer` includes it. `BrowserTesting` adds `TestInstalledApp` and `TestAppBadge`.

- [#175](https://github.com/thomasfosterau/effect-ext/pull/175) [`147be83`](https://github.com/thomasfosterau/effect-ext/commit/147be83ee06f5ad000bcf418cfafa0871ab3d1da) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Performance` to effect-platform-worker-shared: high-resolution time, user timing (`mark`, `measure`, `timed`) and the performance timeline as a stream (`observe`), the same in a window and every worker, as a context reference over the ambient `performance`. Add `WebVitals` to effect-platform-browser: LCP, CLS, INP, FCP and TTFB as streams over that timeline, each a pure fold that runs over fixture entries, plus `BrowserTesting`'s `TestPerformance`, a timeline on a manual clock.

- [#197](https://github.com/thomasfosterau/effect-ext/pull/197) [`41de55f`](https://github.com/thomasfosterau/effect-ext/commit/41de55fb03e247a2bafd2e53d847d58ce8d84259) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Peer on `effect` `^4.1.0` (and `@effect/platform-browser` `^4.1.0` for the browser package). They use `FileSystem.DirectoryEntry`, `FileSystem.lstat` and `Semaphore.takeScoped`, which first shipped in Effect 4.1.0, so the old `^4.0.0` range was never met.

- [#199](https://github.com/thomasfosterau/effect-ext/pull/199) [`32689b6`](https://github.com/thomasfosterau/effect-ext/commit/32689b608ab4a6425ada98d6e53c4a98a1ad6cd8) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `TaskScheduler` to effect-platform-worker-shared: an `effect/Scheduler` over `scheduler.postTask` (falling back to a `MessageChannel`), with `layer`, `withPriority` and `yieldToMain`. Add `Frames` to effect-platform-browser (animation frames and idle callbacks), part of `Browser.layer`, with the `TestFrames` double.

- [#211](https://github.com/thomasfosterau/effect-ext/pull/211) [`6516e9a`](https://github.com/thomasfosterau/effect-ext/commit/6516e9a3532092b296755cf33ff82cb86e823cf2) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `Serial` to `effect-platform-worker-shared`: Web Serial from a window or a dedicated worker. `request`, `ports` and `connections` reach the granted ports; `open` holds a port for a scope and returns a `Connection` that streams reads, writes bytes and sets the control lines, and closes the port when the scope closes. `BrowserTesting` gains `TestSerial`, in-memory ports to drive it.

- [#212](https://github.com/thomasfosterau/effect-ext/pull/212) [`2b05221`](https://github.com/thomasfosterau/effect-ext/commit/2b05221d425df5597537142f436b59413589a3f9) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Adds `Usb` to `effect-platform-worker-shared`: WebUSB from a window or a dedicated worker. `request`, `devices` and `connections` reach the granted devices; `open` holds a device for a scope with a configuration selected and an interface claimed, and returns a `Handle` for bulk, interrupt and control transfers (with `inbound` streaming an endpoint's reads). `BrowserTesting` gains `TestUsb`, in-memory devices to drive it.

- [#165](https://github.com/thomasfosterau/effect-ext/pull/165) [`36f1784`](https://github.com/thomasfosterau/effect-ext/commit/36f1784a83a61c7a122fc670b627461c89335b2f) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - New packages. `effect-platform-worker-shared`: the worker global as a context reference, a worker `runMain`, and schema-typed `postMessage` endpoints. `effect-platform-worker`: dedicated and shared worker globals, their names and lifecycle, and their pages as endpoints. `effect-platform-service-worker`: Cache Storage, the caching strategies and `fetch` routes, extendable-event listeners, persistent notifications and the worker's clients, all from inside the worker. Its `Caches`, `Fetch`, `Events` and `Notifications` modules are effect-ext's former `ServiceWorker` subpath.
